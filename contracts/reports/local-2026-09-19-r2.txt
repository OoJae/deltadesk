Review fixes in this run
- src/libraries/RangeRules.sol (HIGH): the placement fence skipped the bid check when tickLower == slot0.tick. v3
  counts that range as in range and holds token1 on [1.0001^tc, P), so with the pool parked far above the band a
  range [tc, tc + w) bid at the manipulated price. Reproduced on the old code: pool parked at the top of an aligned
  tick 4,000 above the reference, [tc, tc + 20) at full shares, pool swapped back: fence-valued loss $0.645 on $26.96
  deployed, 2.4x the 1% band allowance ($0.270). The finder measured 83% of notional at +46,000 ticks. Fix:
  `if (tl < tc)` -> `if (tl <= tc)` for the bid side (one character; bytecode size unchanged). NatSpec updated.
- src/DeskLaneFactory.sol (MEDIUM): lanesOf(owner) was writable by anyone (a stranger could list an attacker-operated
  lane at the ceiling caps under a victim). Now a lane goes into lanesOf(owner) only when the owner itself sends
  createLane (event LaneListed; view listed(lane)). createLane stays permissionless: a lane deployed for (or
  front-run against) an owner is created but not listed, and the owner's own createLane with the same params returns
  it and lists it instead of reverting (any other repeat reverts LaneExists). isLane still marks every clone (it vouches
  for the code, not for intent).
- src/DeskLaneFactory.sol (MEDIUM): setImplementation applied at once, so the admin could swap the code under an
  in-flight createLane (reproduced: a drainer deployed at a non-predicted address, isLane true, 25 USDG drained).
  Replacing a registered kind's implementation is now pending for IMPLEMENTATION_DELAY = 24 h (ImplementationProposed,
  pendingImplementation) and applied by applyImplementation. Instant only where no predicted address can change: a
  kind's first registration (the deploy script), disabling a kind (drops a pending one), re-affirming the current
  implementation (cancels a pending one). Frozen interfaces and abi/ are unchanged; the new surface is non-interface.
- Tests: RangeRules brute-force model fixed (the current bucket holds both tokens) plus a fuzz against exact v3
  holdings (LaneMath.amounts); N2 regressions (pool parked far above/below, fence at the executed tick); N6 exitAll
  tolerance of NPM positions/decreaseLiquidity/burn failures; N11 covers rerange, reduce, collect, withdraw and
  withdrawAll as outer calls and checks the inner decision is unspent (HookToken records each attempt); maxRanges
  below MAX_SLOTS; factory lanesOf/timelock regressions; CheckDeployment clone-target check.
- Invariant harness: I10 now derives the fence from exact holdings at the pool sqrt price (it was a copy of the rule);
  evilRerange parks the pool 200-3,200 ticks beyond the band on a tick edge and places a range whose in-range edge is
  the pool tick; evil withdraw amounts are scaled to the lane balance; _modelRerange flags ranges > caps.maxRanges
  (I4); maxRanges = 1 is reached more often and the evil operator then sends a valid ask+bid pair. New canaries:
  an operator-callable withdraw (I1 + I8, paying the caller or the owner) and a bid at a parked pool tick (I10).
